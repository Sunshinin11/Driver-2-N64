# Tiny3D: primeira comparação após correção das matrizes

Teste executado em 31/10/2026, Ares v148 no Windows, Chicago, roteiro D2_BENCH.
O usuário confirmou visualmente que os prédios cinza passaram a aparecer.
Isso valida a chegada de geometria à tela; não valida texturas, iluminação ou oclusão final.

## Configurações

- Controle: D2_T3D_WORLD=0, D2_BENCH=1, D2_PERFDBG=0.
- Nativo: D2_T3D_WORLD=1, D2_BENCH=1, D2_PERFDBG=0,
  D2_EXTRA=-DD2_T3D_STATS (contadores agregados leves, desligados por padrão).
- Mesmas opções padrão de otimização. Configuração do usuário copiada para arquivos
  de teste; nenhuma alteração na configuração original. As instâncias de teste são
  encerradas por PID próprio pelo script tools/measure_t3d.ps1.
- Comparação restrita às janelas CameraCnt 64 e 96, antes da aceleração automática.
  Não é replay de estado serializado: variações de execução e layout do código não
  foram isoladas. Uma execução por variante, sem intervalo de confiança.

## Interpretação

O Tiny3D funciona e houve ganho pequeno nesse teste. A hipótese de que quase
nenhum prédio estaria migrado não é sustentada pela contagem deste trecho.
O trabalho restante (incluindo chão, carros, efeitos e o backend antigo) ainda
consome quase todo o orçamento. A distribuição atual desses custos precisa de
novo perfil; o teste não demonstra qual deles domina hoje.

O comparativo não é de qualidade visual equivalente: prédios nativos ainda são
sem textura. Não extrapolar este ganho para o renderizador final texturizado,
outras regiões, outras cidades ou hardware real.

Próximo experimento: atribuir tempo do backend antigo por origem, com marcações
amostradas ou agregadas; escolher entre chão, texturas e objetos dinâmicos a partir
desse perfil. Não usar a quantidade total de modelos convertidos como medida de ganho.

A ROM principal d2_n64.z64 foi restaurada da versão manual
d2_n64_t3d_matrices.z64, sem roteiro automático e sem os novos contadores.
As ROMs *_bench.z64 são exclusivamente para os testes automáticos.
